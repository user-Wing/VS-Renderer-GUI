# 780M：D3D12 / SM6 / FP16与Anime4K实测（2026-11-11）

## 结论与落地

用户本轮明确授权性能测试，可暂停FFmpeg，完成须恢复。**采用D3D11上的FP32重建/像素重排融合，不启用未经证明更快的D3D12后端，不降低整个管线精度。**

Mode A原49个包pass变46个，1080→2160实际执行38→35个。把3路112通道1×1重建及Depth-to-Space融合为一次：每个目标像素只计算所需的子像素分量，减少3张1080p RGBA16F中间纹理（约47.5MiB）和对应写读。保持权重、原算法中间FP16舍入（显式f32tof16/f16tof32）及原alpha=c2语义。没有改色彩、解码、Native ABI或底图精度。

最终三轮交替，GPU执行中位数：

| 原旗舰A | 46.236 / 46.551 / 47.788 | 修正完整RGBA后的最终对照 |

## 硬件与计时边界

- AMD Radeon 780M，驱动32.0.21030.2001；D3D12查询SM6.6/native16/wave32..64支持。
- 用户F盘VCB Kantai Collection 01，1920×1080 HEVC10bit、24000/1001；固定3840×2160；300、600、1000秒帧。未改源文件。
- GPU独立基准使用真实视频帧、常驻RGBA16F输入及hardware timestamps，预热后60帧，交换顺序3轮；不含解码、上传、读回和呈现。检查并发播放器并记录guard；早期NGU并发/启动波动数据保留但不作为收益结论。
- 完整播放器另用真实Qt Player、已有Native DLL和ETW计时，实际截图3840×2160且检查空间内容。显示器29.97Hz，未改显示模式。

## D3D12 / SM6 / FP16结果

同一算法独立执行器：D3D12+原DXBC约40.34–41.28ms；D3D12+DXC/SM6 FP32约40.80–42.20ms；D3D12融合约36.63–37.26ms，而同批D3D11保守融合约33.68–34.72ms。D3D12 CPU录制更低（约0.13–0.17ms对0.18–0.22ms），但GPU计算瓶颈未被API切换解决。

全CNN min16/原生FP16候选误差和性能均不理想：广泛SM6 FP16 RGB最大差约0.0151，未稳定快；局部末级FP16约40.5–41.3ms，也未超过纯FP32融合。不采用。wave功能只做能力查询，未虚称已实现wave/tiled-compute优化。D3D12仍有未来优化空间，本轮不是其所有实现的性能上限。

## 正确性与中间失败（不可省略）

1. 早期独立compare只比较RGB，报告零差并不等于RGBA全部一致；最初融合遗漏alpha=c2，最终已修复。
2. 最终RGBA：300秒、奇数噪声、普通噪声字节一致；600秒出现一个alpha半精度ULP差（最大0.000976562、平均2.94e-11），不能说所有画面完全无差。RGB不变。
3. 新Qt回归最初同一context连续执行而未ClearState/预热，原版对原版也出现差异；加清理/预热后的基线自比较先通过，再测候选。最终奇数2×、1×、1.5×、2.5×、4×完整RGBA字节一致，7通过含init/cleanup。测试严格容差未放宽。
4. 既有shader定向回归16通过0失败0跳过；含增强空间内容、16纹理、多pass、缓存与拒绝非法契约。不是整个产品全量验收。
5. 新Full EXE确实启动实片、可见窗口、提取出与最终优化包SHA相同的内嵌shader并正常关闭。Full/Lite均重新链接。

## 完整播放尚未稳定24

早期实片A/B有9–24fps的大幅波动。保守融合最后一次短对照：原18.63fps/75丢帧、融合20.91fps/43丢帧；ETW GPU busy中位53.06→46.18ms。另一候选曾23.83fps/2丢帧，但不能挑这一轮宣称稳定24。以上短对照在最终alpha修正前；最终修正版做了GPU复测与生产EXE烟测，没有新的长时FPS验收。

Shader独立34–40ms不等于整帧34–40ms。真实链还有解码/色彩转换/末级缩放/同步与呈现；共享内存压力和调度仍需后续隔离。A+额外增强仍超过41.7ms，仅GPU侧就没有可靠24fps余量。此轮未改自动解码跳帧策略、D3D11合成器或第二缩放语义。
