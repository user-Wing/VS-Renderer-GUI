# MoeSR、1X 与共享 HLSL 优化（2026-11-11）

本轮沿用已交付的旗舰 A 优化。只采用通过数值回归且在同组交替 A/B 中持续更快的候选，不降低模型、运算精度或画质档位。MoeSR 没有实时目标。

## 采用与保留

- MoeSR：只对末端 11 个卷积 pass 按纹理整理访问/累加顺序。保留 52 pass、全部权重、FP32 运算、FP16 中间表面与原像素重排。累加顺序变化存在舍入误差，不能称为无损或位精确。
- 1X：通过已有 CustomShader 包 API 执行同一模型，将同尺寸整数偏移的采样改为边界钳制的 Load。包的 OUTPUT 表达式固定为 NATIVE，保持输入尺寸；保留 Jinc/D3D11 最终缩放、用户第二次缩放设置及原生 1X 失败回退。Full/Lite 共用路由。
- 共享入口：`ShaderPackage::enhance` 的三种受控增强在当前 LUMA 尺寸上使用整数 Load，3×3/5×5 边界钳制。没有改写任意第三方着色器、通用导入器、资源规划或 Native ABI。
- Fast/Fast+/noCNN/noCNN+：通用包候选在部分小尺寸与倍率下没有满足严格逐位验收，原执行器保留。reference 包重复运行自身也观察到微差，原因未定，不能把初始 1080p 零差推广为普遍结论。

## GPU 计时

AMD Radeon 780M，驱动 32.0.21030.2001。输入为本机真实 1920×1080 HEVC10bit 视频的 300 秒帧，目标 3840×2160。每次先预热 8 次，采集 48 次硬件 timestamp，五轮交替先后顺序，串行执行。每次调用检查独立编码保护租约与竞争进程，最长 120 秒。

| 项目 | 原版中位数 ms | 候选中位数 ms | 节省耗时 | 更快轮数 |
|---|---:|---:|---:|---:|
| MoeSR 整个 shader 链 | 169.87488 | 161.40299 | 4.99% | 5/5 |
| 1X 整个 shader 链 | 7.18164 | 6.52888 | 9.09% | 5/5 |
| sharpen_edges 单 pass | 0.52816 | 0.36904 | 30.13% | 5/5 |
| enhance_detail 单 pass | 1.16188 | 0.72444 | 37.65% | 5/5 |
| crispen_edges 单 pass | 0.53732 | 0.38280 | 28.76% | 5/5 |

共享单 pass 计时使用 1080p RGBA16F，完整增强链还包括 LUMA 提取与合并。所有表格数据均不含解码、输入上传、回读与呈现，不是完整播放器 FPS。不同轮次的旗舰 A 数字不用于此轮收益计算。

## 数值检查与拒绝记录

扩展前固定标准：轻档完整 RGBA 逐位一致；MoeSR 最大绝对误差不超过 1/1024、平均不超过 1e-6、alpha 一致、不产生非有限值。没有为过测试放宽标准。

每个模型覆盖 14 个输入/尺寸组合：300/600/1000 秒真实帧、噪声、奇数 319×181、渐变、棋盘、1×/1.5×/2×/2.5×/4×、黑/白、边角与中心脉冲、高频条纹、多 alpha。输入接口是归一化 RGBA64；它不能表示 NaN/Inf，所以“非有限值为零”是输出检查，不是 NaN/Inf 输入兼容结论。

MoeSR tail11 两次完整检查通过，最大误差 0.0009765625，最高平均误差约 3.28e-7；alpha 一致。1X 两次 14/14 逐位一致且输出字节数始终等于输入尺寸×8。共享三种增强独立 12 组 RGBA 逐位一致。

原 MoeSR 43 pass 全重排在噪声输入的 MAE 约 1.22e-5，拒绝；三重建融合、显式 FMA、预取、纹理池和常量更新候选没有稳定收益，未采用。完整原始失败结果保留在证据目录。

安装自带 `D3DCOMPILER_47.dll` 的实际 API 组合包另测21组，18组逐位一致，A的小尺寸噪声/奇数/alpha三项非零；这些整链零差检查仍记为失败。旧增强A对自身重复同样有非零差异。将同一份带负值的FP16 CNN输出固定上传，再运行实际旧/新两段增强，三个原失败输入均完整RGBA逐位一致。由此隔离出共享增强没有增加该固定输入的误差，但底层整链重复不稳定的根因未解决，不能称整个A始终位精确。

安装编译器对应的完整A+增强GPU三轮为原43.35516/42.04584/42.92304ms、新40.91344/41.04832/42.64428ms；中位数节时4.37%，3/3更快。系统编译器另组约3.53%节时，独立保留，未与安装环境混算。最终删除已不使用的Sampler声明后，新API增强包仍逐字节相同，SHA为`d6dfbf7076b64752b7999e0e73716a297a9109d931bea25cee2a325e6d3b678e`。

Full/Lite真实播放专项各3通过，shader专项18通过，原A五倍率回归7通过，均含init/cleanup。实际十档画面、暂停/恢复/seek、1X两种最终缩放差异、包指纹、清包和损坏包回退已覆盖。这些专项不是全量产品、HDR色准或长期播放器FPS验收。

## 重建与回退

```powershell
python tools/optimize-moesr-tail.py
python tools/convert-anime4k-fast.py
python tools/package-anime4k-1x.py
```

MoeSR 生成器固定源和原包 SHA；参考包位于 `tests/fixtures/moesr-50k-reference.vsrhlsl`。1X 生成器固定原 GLSL 与转换清单 SHA，保留原许可证并生成语义一致的 1X GLSL 回退源。两种生成器均已重建出与实测候选逐字节相同的包，元数据记录源码与包 SHA。

本轮不需要新 Native DLL：共享增强生成、资源和路由位于 GUI。已知完整 Native 构建缺齐套 MSVC IAMF/libass/FFmpeg SDK，不把独立基准或 GUI 构建称为完成 Native 全量构建。未采用纹理复用等仅改 Native 头的实验。
