# 基础色彩与 VS 恒等帧桥修复（2026-11-14）

## 实施范围

按用户要求先修原生基础色彩，再补VS帧桥。固定上游仍为 `248cb9bb0cef91922ab8f88ea7f6ef38ec0e311c`；独立工作树 `.deps/fff-color-fix-20261114` 避开原集成目录的未完成合并。修改整合到 `patches/3fp-vsp-upstream-20261113.patch`，标准脚本复制新增元数据头文件。

本轮不修改版本、不提交上游PR、不推送或发布，保留无关改动。历史边界见 [讨论修正](color-audit-followup-20261107.md)。本记录描述本轮修复，历史审计失败数字不再直接代表新产物。

## 基础颜色处理

- 修正显式线性整数RGB、sRGB、Gamma2.2/2.8、240M传递函数。普通709既有直通策略保留；需要转换时在正确线性域处理并编码到SDR目标。
- 显式709原色不再因HDR分类被当作2020。补Display P3、DCI白点适配、SMPTE C和PAL转换，P3到SDR不再原码值直通。
- CL采用分段色差还原及准确2020非线性常数；普通/线性/全景采样共用YUV还原函数。补FCC、240M、YCgCo；未实现的显式矩阵/原色/TRC明确拒绝，避免静默按601/709解释。
- 无标签的普通子采样YUV在软件与D3D11路径统一LEFT；JPEG旧全范围格式保留CENTER，在VS源中显式表达，防止格式名称变化后失去默认语义。
- 浮点RGB/Gray直接打包RGBAF32上传，不经整数swscale，32位源及对应中间缩放纹理用32F，保留负值/超白。一般浮点输入尊重显式TRC/原色；旧未标记packed FP16 JXR仅保留窄范围历史scRGB推断。
- 保留上游HLG共同亮度因子；没有改变显示端HDR元数据策略或额外叠加应用端tone mapping。

## VS交换契约

外部帧v2保留112字节v1前缀，追加128字节 `VsrFrameColorMetadata`，Qt/Native共用头文件并检查布局。通过可选能力查询协商；旧Native只接受不需要新能力的v1输入，浮点或新metadata要求明确报不支持。

支持整数Gray/YUV/RGB和RGBH/RGBS/GRAYH/GRAYS。基础CICP及RGB→GBR平面顺序继续保持，新增：

- 标准VS mastering原色/白点/亮度与MaxCLL/FALL；公开静态属性优先于私有旧载荷。
- 隔行标记、SAR、逐帧PTS和持续时间；有PTS时不再按帧号乘单帧时长伪造位置。
- 同FFmpeg ABI的私有side data，白名单为mastering、CLL、HDR10+、Vivid；验证版本、类型、长度及动态数组计数。
- 流级HDR10+类别和有界间歇持有；新流/倒退/重复帧及类别变化重置状态。补齐本帧SEI完全缺失时的持有条件及外部帧snapshot HDR状态发布。
- 显式输出格式转换从已导入metadata的帧复制属性，并按RGB/YUV目标重新标记矩阵/范围；无法正确处理的CL/YCgCo等组合拒绝。恒等链不启用此转换。

新增 `NativeVsSource.cpp` → `vsr-source.dll`，使用与Native相同FFmpeg运行库软件解码，将样本原值放入VS平面，携带帧信息及流级补充。RGB24/48只拆包，不改变数值。按真实解码序号建索引，不按名义fps猜VFR帧号。

Renderer源列表新增“3FP 原生（色彩保留）”，新配置默认使用它；旧源选择记忆保留。Player新建VS模板及空预设VS路径使用它，现有用户VPY不重写。显式L-SMASH/FFMS2仍按原脚本执行，其元数据完整性取决于对应插件。

源提供像素摘要/CICP签名：输出仍对应原样本与编码时允许原始HDR载荷通过；改变像素后剥离继承的动态载荷，编码改变时同时清除继承的静态HDR属性。明确重生成metadata的滤镜可设 `_VsrColorMetadataValid=1`，并承担新属性的正确性。普通无HDR载荷SDR源不额外逐字节计算摘要。

**滤镜仍处理源信号，再由统一3FP显示链输出。** 恒等链验证不意味着将所有滤镜移到显示tone mapping之后。需要线性光或显示参考输入的滤镜应明确转换并更新输出标签。

DV不在主线传递重塑/FEL载荷。新源仅允许明确HDR10/SDR/HLG兼容底层回退；没有受支持兼容底层时拒绝。Vivid保留既有识别/峰值能力，不声称新增完整Vivid曲线。

## 当前限制

1. 实际加载含 `vsrsource.Source` 的VPY时，原生VS源首次完整解码建索引，倒退可能重新顺序解码。正常原生播放及原生HLSL/转换GLSL路径不触发；经VS执行GLSL则取决于所选源插件。长片首开/定位开销尚未优化。
2. Alpha、BE、位打包RGB、部分罕见位深/子采样及变尺寸/变格式流明确拒绝；含Alpha的JXR/scRGB不属于当前VS恒等范围。
3. 真实复杂VFR媒体全链路仍需专项验收；已有PTS交换及源索引不等于全部时序行为已验收。
4. 恒等条件是受支持Native源、未额外指定格式转换、同一源帧和相同渲染设置。滤镜造成的采样/量化/色彩变化由滤镜定义，不能无条件恢复旧动态曲线。

本地部署及保护文件哈希见 [验证摘要](evidence/color-fix-20261114/summary.json) 与 [部署记录](evidence/color-fix-20261114/deployment.json)；源码推送和发布不属于本轮。
